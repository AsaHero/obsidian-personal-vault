## От сумматора к другим операциям

Если продолжить абстракцию дальше, из [[3. Adders|сумматора]] можно собрать и другие операции.

### Инкремент

Если взять обычный сумматор и **зафиксировать второй вход равным 1** (постоянная единица на самом младшем разряде, нули на остальных), получится схема инкремента (+1):

![[8bit_increment.gif]]

### Вычитание и декремент

Точно так же можно собрать **полный вычитатель (full subtractor)**, а из него — 8-битный subtractor и декремент:

![[8bit_subtractor.gif]]

Но для вычитания необязательно городить отдельную схему с нуля — можно переиспользовать уже готовый сумматор. Числа в процессоре хранятся в **дополнительном коде (two's complement)**, а в нём вычитание — это то же сложение:

```
A - B = A + (NOT B) + 1
```

То есть достаточно пропустить B через [[1. Transistors|инверторы]] (получить его побитовое NOT) и подать результат в тот же full adder, что и раньше, дополнительно подав `1` на самый младший Cin. Декремент, соответственно — это "инкремент наоборот": тот же сумматор с инвертированным входом и Cin = 1.

Так из одной и той же схемы сумматора, комбинируя входы, получаются сложение, вычитание, инкремент и декремент — и дальше можно придумывать операции сложнее.

## Как процессор выбирает операцию

Внутри процессора есть специальный компонент, который хранит все эти схемы и умеет выбрать нужную — **арифметико-логическое устройство** (АЛУ, англ. _Arithmetic Logic Unit, ALU_).

Возникает вопрос: когда процессор выполняет инструкции, как он понимает, какую схему запустить — тем более что часть инструкций вообще не про арифметику:

```
LOAD [a] R0  ;Load value of memory address [a] in Register_0
LOAD [b] R1  ;Load value of memory address [b] in Register_1
ADD R0 R1    ;Add Register_0 with Register_1 and write the result in Register_0
SUB R0 R1    ;Subtract Register_1 from Register_0 and write the result in Register_0
STORE R0 [a] ;Store value in Register_0 in [a] memory address
LOAD [c] R0  ;Load value of memory address [c] in Register_0
DEC R0       ;Decrement value in Register_0
```

(Как именно инструкция проходит fetch → decode → execute → write, подробно разобрано в [[11. Instruction Cycle]].)

Тут на сцену выходит [[4. Binary Decoder]].

По сути, инструкция — это просто человекочитаемое представление машинного кода (реальных нулей и единиц):

![[Media/Pasted image 20260905011721.png]]

Внутри инструкции есть биты, которые вообще не про арифметику. Соберём самую примитивную схему их различения:

Если **первые 2 бита** инструкции = `00` → это арифметическая инструкция. Проверяется одним [[2. Logic Gates|NOR]]-вентилем: NOR выдаёт 1, только если оба его входа — 0, то есть ровно тогда, когда первые два бита инструкции — `00`.

![[Media/Pasted image 20260905012022.png]]

**3-й и 4-й биты** — это **опкод** (operation code, opcode), который определяет конкретную операцию:

| Опкод (биты 3–4) | Операция  |
| ---------------- | --------- |
| 00                | Сложение  |
| 01                | Вычитание |
| ...               | ...       |

Каждый опкод соответствует ровно одной арифметической операции.

![[Media/Pasted image 20260905012225.png]]

Пусть процессор уже понял по первым двум битам, что это арифметическая операция — теперь нужен decoder, который по опкоду выберет конкретную схему внутри ALU:

![[Media/Pasted image 20260905012437.png]]

Самый простой вариант: подать значения регистров на входы **всех** схем сразу (сложение, вычитание и т.д. считаются параллельно), а на выходе через [[4. Binary Decoder|binary decoder]] пропустить наружу только результат той схемы, на которую указывает опкод:

![[alu_decoder.gif]]

Это упрощённый и не самый эффективный способ (в реальности схемы не считают "всё подряд, а лишнее выбрасывают" — так впустую тратится энергия), но он хорошо показывает сам принцип работы.

## ALU целиком

Инкапсулируем всё в один компонент:

**АЛУ (арифметико-логическое устройство)** принимает входные значения и опкод, который указывает внутренней схеме, какую операцию выполнить. АЛУ выдаёт результат операции плюс дополнительные флаги:

- **Zero** — результат равен нулю;
- **Negative** — результат отрицательный;
- **Overflow / Carry** — произошло переполнение (см. [[3. Adders#8-bit adder|overflow в сумматоре]]).

![[Media/Pasted image 20260905013406.png]]

Это и есть главный вычислительный узел процессора, работающий рука об руку с [[7. Registers|регистрами]] — а теперь понятно, из чего он на самом деле собран: транзисторы → [[2. Logic Gates|вентили]] → [[3. Adders|сумматоры]] и [[4. Binary Decoder|decoder]] → ALU.

Но откуда ALU вообще берёт `R0`, `R1` и другие значения, с которыми работает, и куда девается результат между операциями? За это отвечают регистры — а чтобы понять, как они умеют хранить биты, сначала нужно разобраться, как из вентилей вообще получить схему с памятью. Переходим к [[6. Memory]].
