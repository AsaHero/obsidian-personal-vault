## Мультиплексор: выбор операндов

Для операции нужно прочитать до двух значений из регистров и подать их на два входа ALU. Можно тупо завести все регистры на оба входа и читать только нужные — но чище использовать **мультиплексор** (по сути роутер): из нескольких входных шин он пропускает на выход ровно одну, по номеру-селектору.

![[multiplaxar.gif]]

Мультиплексор — это [[4. Binary Decoder|декодер]] наоборот: декодер по номеру активирует один из выходов, мультиплексор по номеру выбирает один из входов (и собрать его можно из того же декодера).

Ставим по мультиплексору на каждый вход ALU. Варианты на входе — шины данных всех регистров; селекторы — две последние пары битов инструкции (номера регистров-операндов); а Read Enable регистров включает сигнал от декодера типа инструкции:

## Цикл: Fetch → Decode → Run → Write

**Address Register** хранит адрес *следующей* инструкции. Сейчас там `0000`. Процессор крутит один и тот же цикл:

1. **Fetch** — Address Register выставляет свой адрес на адресную шину RAM, включается Read Enable памяти и Write Enable у Instruction Register: инструкция из памяти по этому адресу попадает в IR.
2. **Decode** — декодеры блока управления разбирают биты IR: тип инструкции, опкод, номера регистров, адрес. Определяется, куда пойдут сигналы.
3. **Run** — сигналы идут по схеме: ALU считает, либо память/регистр готовят данные на шине.
4. **Write** — результат записывается: в регистр (из временного регистра) или в память.
5. Address Register увеличивается на 1 — и цикл повторяется со следующей инструкцией.

> Инструкции перехода (`JUMP`, ветвления) просто записывают в Address Register новый адрес вместо инкремента — поэтому следующий Fetch берёт инструкцию из другого места.

> В этом упрощённом процессоре Address Register выполняет роль Instruction Pointer из [[7. Registers#Регистры в процессоре|конспекта про регистры]]. В реальных процессорах адрес следующей инструкции (IP/PC) и адрес для обращения к памяти — это два отдельных регистра.

## Чего здесь нет: Clock

В этом разборе пропущен один важный элемент — **тактовый генератор (Clock)**. Шаги цикла должны идти строго по очереди: сигнал должен успеть устояться на всех проводах, прежде чем схема перейдёт к следующему шагу. Clock — это метроном, который задаёт ритм и не даёт шагам наезжать друг на друга.

Как именно тактовый сигнал технически заставляет схему переключаться ровно между Fetch, Decode, Run и Write — от простого генератора прямоугольных импульсов до готового счётчика, перебирающего эти четыре шага, — разбираем в [[13. Clock|следующих трёх конспектах]].

Отсюда же растут тактовая частота, конвейер и многоядерность — но это уже [[17. Pipelining|отдельная история]].
