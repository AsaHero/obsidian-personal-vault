## Полусумматор (half-adder)

Сложение бинарных чисел работает так же, как привычное десятичное:

```
0 + 0 = 00
0 + 1 = 01
1 + 0 = 01
1 + 1 = 10
```

Значит, нужна схема с **двумя выходами**: сумма (Sum) и перенос (Carry).

![[Media/Pasted image 20260904181320.png]]

| A   | B   | Carry | Sum |
| --- | --- | ----- | --- |
| 0   | 0   | 0     | 0   |
| 0   | 1   | 0     | 1   |
| 1   | 0   | 0     | 1   |
| 1   | 1   | 1     | 0   |

Начнём с колонки Sum — она в точности совпадает с [[2. Logic Gates|XOR]]:

![[sum_gate_0.gif]]

А колонка Carry идентична [[2. Logic Gates|AND]] — перенос появляется, только когда оба входа единицы:

![[sum_gate_1.gif]]

Вместе — готовая схема, которая складывает два бита:

![[sum_gate_3.gif]]

Отлично, но как быть с многозначными числами, например `111 + 101`? Если прогнать это сложение через нашу схему поразрядно, переносу из младшего разряда просто некуда деться — у схемы нет входа, куда его подать:

![[half_adder.gif]]

Поэтому то, что мы собрали, называется **полусумматор (half-adder)**.

⚠️ Проблема: у полусумматора только **2 входа** — он не умеет учитывать перенос из предыдущего разряда, поэтому для сложения многозначных чисел не годится.

## Полный сумматор (Full Adder)

Нужна схема с **3 входами**: два складываемых бита + перенос из предыдущего разряда (Cin). Выдаёт Sum и перенос дальше (Cout).

```
        ┌────────────────┐
 A  ───►│                │
 B  ───►│   Full Adder   ├───► Sum
Cin ───►│                ├───► Cout
        └────────────────┘
```

Схема полного сумматора:

![[full_adder.gif]]

Чтобы сложить многозначные числа, нужно взять столько полных сумматоров, сколько разрядов в числах. Например, для `111 + 101` нужно 3 полных сумматора, соединённых в цепочку, где Cout каждого идёт в Cin следующего:

![[n_full_adder.gif]]

Такая схема называется **ripple-carry adder** (сумматор с последовательным переносом) — чтобы сложить n-битные числа, нужно n полных сумматоров. Например, для 8-битных чисел — 8 полных сумматоров:

![[Media/Pasted image 20260904234916.png]]

> ⚠️ Оговорка про скорость: сигнал по проводу бежит почти мгновенно, но **каждый вентиль вносит небольшую задержку** (доли наносекунды). В ripple-carry adder перенос должен последовательно пройти через все n сумматоров — Cout второго разряда не может появиться, пока не готов Cout первого. Поэтому итоговая задержка всей схемы растёт линейно с числом разрядов: 64-битный ripple-carry adder заметно медленнее 8-битного. Именно поэтому в реальных процессорах используют более сложные схемы (например, carry-lookahead adder), которые вычисляют все переносы параллельно, а не по цепочке.

### 8-bit adder

Инкапсулируем логику 8-битного сумматора в одну логическую единицу:

![[Media/Pasted image 20260904235541.png]]

**Overflow** — флаг переполнения: он сообщает, что результат не поместился в 8 бит. По сути это Cout самого старшего разряда. Пример:

![[Media/Pasted image 20260905003632.png]]

Ориентируясь на overflow, можно либо сообщить об ошибке, либо выделить под результат дополнительное место (например, перейти с 8 бит на 16):

![[overflow_singal.gif]]

> Это верно для **беззнаковых** чисел. Если числа хранятся в дополнительном коде (знаковые, two's complement), переполнение определяется иначе — сравнением переноса **в** знаковый бит и переноса **из** знакового бита (если они не совпадают — знаковое переполнение), и Cout сам по себе уже не показатель.
