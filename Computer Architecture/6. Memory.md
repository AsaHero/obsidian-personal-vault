Память — это способность схемы сохранить кусочек информации во времени: один раз получить сигнал на входе и после этого «помнить» его, даже когда сам сигнал уже пропал. Всё, что мы собирали до этого — [[2. Logic Gates|вентили]], [[3. Adders|сумматоры]], [[4. Binary Decoder|декодер]] — это **комбинационные** схемы: их выход зависит только от текущих входов. Память — первая **последовательностная (sequential)** схема: её выход зависит ещё и от того, что происходило раньше.

## Обратная связь: вентиль, зацикленный сам на себя

Самая простая идея — завести выход вентиля обратно на один из его же входов.

Возьмём OR-вентиль и соединим его выход со вторым входом:

![[or_raw_mem.gif]]

Если на свободный вход подать 1, на выходе, как обычно для OR, появится 1. Но эта единица тут же идёт обратно на второй вход. Дальше OR продолжает выдавать 1, даже если внешний вход вернётся в 0 — вентилю достаточно единицы хотя бы на одном входе, а один вход у него теперь навсегда подключён к собственному выходу. Схема «запомнила», что когда-то на входе была единица, и держит это состояние сколько угодно (пока идёт питание).

Похожий трюк работает и с AND, только в обратную сторону:

![[and_raw_mem.gif]]

Если оба входа AND держать в единице, на выходе тоже 1, и один вход зациклен на выход. Но стоит внешнему входу хотя бы раз стать 0 — выход упадёт в 0 и там же и останется: AND с одним нулевым входом всегда выдаёт 0, а этот 0 дальше сам себя поддерживает по петле обратной связи.

⚠️ Проблема: у каждой из этих двух схем только одно устойчивое «запоминаемое» значение. OR-петля умеет держать 1, но, попав в 1, никогда не вернётся в 0. AND-петля — наоборот, умеет держать 0, но, попав в 0, никогда не станет 1. Нужна схема, которая по команде умеет переключаться и в 0, и в 1.

## Первая попытка: соединить AND и OR

Раз одна петля хорошо держит 1, а другая — 0, напрашивается соединить их вместе:

![[Pasted image 20260905203941.png]]

OR по-прежнему зациклен сам на себя, но его выход теперь идёт в AND вместе со вторым, независимым входом. Результат AND — это выход всей схемы, и он же возвращается обратно в OR.

Если на мгновение подать 1 на **оба** входа — на выходе появится 1: OR выдаёт 1, AND пропускает его дальше, потому что второй вход тоже 1. Дальше первый вход можно вернуть в 0 — ничего не изменится, OR продолжает держать себя сам через обратную связь. А вот если в 0 увести **второй** вход — AND сразу обнулит выход, и вслед за этим развалится и петля OR, которой больше неоткуда взять единицу.

Получается несимметрично: чтобы **запомнить 1**, нужно на мгновение подать 1 на оба входа сразу. А чтобы **сбросить в 0**, достаточно увести в 0 только второй вход — независимо от первого. Работает, но смысл входов какой-то перевёрнутый: чтобы просто удерживать уже сохранённую единицу, второй вход обязан всё время оставаться равным 1, а не 0.

## SR-защёлка: добавляем NOT

Чтобы входы обрели привычный смысл «1 = действие», поставим перед вторым входом инвертор:

![[Pasted image 20260905204444.png]]

Теперь у схемы два понятных входа:

- **SET** — идёт напрямую в OR. Подать на него 1 → выход становится 1.
- **RESET** — идёт через NOT. Подать на него 1 → выход становится 0.

Подаём 1 на SET:

![[Pasted image 20260905204931.png]]

Выход стал 1. Возвращаем SET обратно в 0 — выход остаётся 1: OR продолжает держать себя через обратную связь, а RESET = 0, пройдя через инвертор, превращается в 1 на входе AND и не мешает.

Теперь подаём 1 на RESET:

![[Pasted image 20260905205840.png]]

RESET = 1, пройдя через инвертор, превращается в 0 на входе AND — AND сразу обнуляется, а вместе с ним разваливается и петля OR. Выход — 0.

| SET | RESET | Выход                   |
| --- | ----- | ------------------------ |
| 0   | 0     | без изменений (хранит)   |
| 1   | 0     | 1                         |
| 0   | 1     | 0                         |
| 1   | 1     | ⚠️ Invalid State           |

![[Pasted image 20260905210044.png]]

Инкапсулируем в единицу — такая схема называется **AND-OR-LATCH** (она же SR-защёлка, Set/Reset latch):

![[Pasted image 20260905210158.png]]

Есть только одна плохая комбинация: если подать **SET = 1 и RESET = 1 одновременно**, обе половины схемы одновременно тянут выход в разные стороны, и получается неопределённое, «недопустимое» состояние (Invalid State). Поэтому SR-защёлку используют с условием, что SET и RESET никогда не подаются вместе.

## Почему один вход Data не работает сам по себе

Хочется управлять защёлкой одним входом Data — 0 значит «сбросить», 1 значит «установить» — а не двумя раздельными SET/RESET. Самое напрашивающееся решение: подать Data напрямую в SET, а через инвертор — в RESET:

![[and_or_latch_improv1.gif]]

Но так теряется сам смысл памяти: SET и RESET теперь всегда противоположны друг другу и всегда активны, и какое бы значение ни было на Data, схема немедленно пропускает его на выход. Она перестаёт что-либо *хранить* и превращается в обычный [[1. Transistors|buffer]] — выход просто зеркалит вход в реальном времени.

Не хватает третьего сигнала, который говорит схеме, **когда** обращать внимание на Data, а когда игнорировать его и держать то, что уже сохранено.

## Write Enable → D-защёлка

Добавляем такой сигнал — **Write Enable (WE)**:

![[Pasted image 20260905212857.png]]

Идея: SET и RESET должны срабатывать только тогда, когда `WE = 1`. Вместо того чтобы подавать Data напрямую, собираем:

```
SET   = Data AND WE
RESET = (NOT Data) AND WE
```

Оба выражения проходят каждое через свой AND с Write Enable, и только после этого попадают в уже знакомую AND-OR-защёлку (RESET, как и раньше, дополнительно инвертируется перед финальным AND):

![[gated_latch.gif]]

Как это работает:

- **`WE = 0`** — оба произведения (`Data AND WE` и `(NOT Data) AND WE`) равны 0 при любом Data. Ни SET, ни RESET не срабатывают — защёлка просто хранит то, что в ней уже было.
- **`WE = 1`** — `SET = Data`, `RESET = NOT Data`. Ровно одно из них всегда равно 1, поэтому защёлка либо устанавливается в 1, либо сбрасывается в 0 — в точности повторяя вход Data. Invalid State при этом физически невозможен: Data и NOT Data никогда не равны 1 одновременно.

Вот и получилась полноценная **1-битная память**, которая называется **D-защёлка (D latch, gated latch)** — «D» от Data:

![[Pasted image 20260905213800.png]]

| WE  | Data | Выход                   |
| --- | ---- | ------------------------ |
| 0   | ×    | без изменений (хранит)   |
| 1   | 0    | 0                         |
| 1   | 1    | 1                         |

> Это не единственный способ построить 1-битную память — например, есть ещё D-триггеры (flip-flops), которые реагируют не на уровень WE, а на его фронт (момент переключения из 0 в 1). Но для понимания сути — как из обычных вентилей получить схему, которая помнит своё состояние, — защёлки достаточно.

Один бит сам по себе почти бесполезен. Дальше объединим несколько таких защёлок вместе и получим то, чем процессор реально пользуется для хранения чисел прямо во время выполнения инструкций — [[7. Registers|регистры]].
