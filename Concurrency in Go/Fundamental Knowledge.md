## Moore's law

Закон мура - количество [[1. Transistors|транзисторов]], размещаемых на кристалле интегральной схемы (процессоре), удваивается каждые 24 месяца.

Был такой закон, и он не плохо работал до 2010 года. Написали код и запускали на одном процессоре, и если обновить свой процессор через два года тот же самый код работал два раза быстрее. Но к 2010 году вот такая тенденция перестала работать. А почему так случилось ?

Так как в последнее время производители процессоров перестали концентрироваться только на вопросах повышения тактовой частоты. Так как уже физически сложно стало уменьшать транзисторы чтоб плотнее расположить еще больше в одном процессоре. 

Вместо этого современные процессоры имеют несколько ядер – **для эффективного использования возможностей этой архитектуры** разработчики должны хорошо понимать особенности конкурентного выполнения программ.

## CPU

Давайте же углубимся в устройство процессора. Стоит начать с вопроса что собой представляет типичная архитектура компьютера ?

Вот это самая база это архитектуры:

```
   ┌─────────────┐  ┌─────────────┐
   │             │  │             │
   │     CPU     │  │     RAM     │
   │             │  │             │
   └─────────────┘  └─────────────┘

   ┌─────────────┐  ┌─────────────┐
   │             │  │             │
   │     IO      │  │   HDD/SSD   │
   │             │  │             │
   └─────────────┘  └─────────────┘
```


CPU - он отвечает за вычисление. Мозги компьютера. 
RAM - Временная память. 
HDD/SSD - Постоянная память.
IO - компоненты взаимодействия с пользователем. (Input/Output)

А что же внутри CPU?

```
   AX = 0x07      ┌──────────────────────┐
   BX   0x05      │ ┌──────────┐ ┌─────┐ │
   ...            │ │ Registers│ │ ALU │ │
   IP = 0xF3      │ └──────────┘ └─────┘ │
                  │                      │
                  │          CPU         │
                  │                      │
                  │                      │
                  └──────────────────────┘
```

Как мы поняли это мозги машины для вычисления, и для этого внутри есть модуль **ALU**. Arithmetic Logic Unit (АЛУ или ALU) — это главный вычислительный блок процессора, который выполняет все базовые арифметические и логические операции с данными (подробный разбор, как ALU собирается из транзисторов и логических вентилей — в [[5. ALU]]). Так же как мы говорили у нас есть временная память (быстрая) и постоянная память (медленная), а у процессора есть еще своя временная память (очень быстрая) которая называется регистрами, которая внутри самого кристалла. И этих регистров есть свой идентификатор, как мы видим AX,BX и так далее и эти регистры общего назначения. Но и также есть Регистры специального назначения такие как IP (Instruction Pointer), который указывает на адрес следующей инструкции который будет выполнено. 

```Go
func main() {
    result := 2 + 5      // 0xF2
    result *= 10         // 0xF3
    fmt.Println(result)  // 0xF4
}
``` 

Когда ваш компьютер выполняет верхний код с какими то вычислениями, там есть адрес каждой инструкции по которым IP пройдется и таким образом код будет выполняется последовательно. 

Но на самом деле не все так просто, чтоб процессору осуществить какие то вычисления, ему нужно дополнительно кое что сделать, и эти доп действия называются трактами данных (datapath):

### Datapath

**ТРАКТ ДАННЫХ**

1. Выборка команды из памяти
2. Декодирование команды
3. Исполнение команды
4. Запись результатов в регистры или память

```
x + y

  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐
  │  Fetch  │ │ Decode  │ │   Run   │ │  Write  │
  └─────────┘ └─────────┘ └─────────┘ └─────────┘
```

Fetch - хорошо в IP у нес есть адрес на след инструкцию. Но сама инструкция в RAM, нужно его загрузить из памяти это и есть Fetch. 

Decode - после того как мы загрузили инструкцию нужно его декодировать (так как инструкция в виде нулей и единиц мне нужно распарсить чтоб понять какая это инструкция: сложить, отнять, прыгнуть в другой участок памяти и тд)

Run - после того как я понял что мне нужно сделать непосредственно нужно его выполнить 

Write - чтоб от выполнения был какой то толк нам нужно результат записать куда то, либо обратно в регистр или в какой то участок памяти (зависит от инструкции).

Вот и те самые неявные действия которые выполняются когда вы выполняет процессор какую либо инструкцию или команду.  


### Superscalar Processor 
Но сейчас большинство процессоров суперскалярные, то есть внутри них есть так называемые ступенчатые пайплайны. Они могут быть 32-ух ступенчатые пайплайны и более. 

Давайте посмотрим на самый простой 4-ех ступенчатый пайплайн:

**ЧЕТЫРЕХСТУПЕНЧАТЫЙ ПАЙПЛАЙН**

| Instruction | 1     | 2      | 3      | 4      | 5      | 6     | 7     |
| ----------- | ----- | ------ | ------ | ------ | ------ | ----- | ----- |
| **x+y**     | Fetch | Decode | Run    | Write  |        |       |       |
| **i++**     |       | Fetch  | Decode | Run    | Write  |       |       |
| **z/2**     |       |        | Fetch  | Decode | Run    | Write |       |
| **j--**     |       |        |        | Fetch  | Decode | Run   | Write |

Можно это представить как завод авто, где каждым этапе работы параллельно по разными авто делают разные детали и действия. Если возьмем 4 временной промежуток из нашей таблицы примерно такое и происходит в одном конвейер происходит Write у операции x+y, Run у i++, Decode у z/2 и Fetch у j--. 

Вот и мы пришли к ступенчатому виду действии нашего процессора, и что дает нам понять кое что очень интересное:

**НЕ ВСЕ ИНСТРУКЦИИ ЗАКАНЧИВАЮТСЯ ОДНОВРЕМЕННО**

Сложение, например, выполняется невероятно быстро, а вот делению или загрузке из памяти может потребоваться на выполнение несколько сотен циклов

ⓘ Современные процессоры вместо того, чтобы простаивать в ожидании завершения одной медленной инструкции, **могут выполнять инструкции вне очереди**. То есть таким образом команды которые попадают в определенном порядке, не всегда означает что они выполнятся этом же порядке, процессор может переупорядочить в зависимости от действии та или иная инструкция нуждается.   

### Processor Bit Width

**РАЗРЯДНОСТЬ ПРОЦЕССОРА**

Число разрядов (их еще называют битами), которые процессор способен обработать за один раз. И регистры внутри этого процессоры как раз таки также 64 битные.  

ⓘ проще говоря, 64-битный процессор может обрабатывать в два раза больше информации, чем 32-битный

То есть операцию над 8 байтовым значением 32-битый процессор не может выполнить за раз, ему нужно будет выполнить сперва страшим 4 байтом операцию потом младшим 4 байтом значение. А вот 64битный процессор за раз выполнит эту операцию 

### Multicore Processors 

МНОГОЯДЕРНЫЙ ПРОЦЕССОР
Процессор содержащий два и более вычислительных ядра на одном процессорном кристалле

Схема справа:

```
┌───────────────────────┐
│ ┌────────┐ ┌────────┐ │
│ │  Core  │ │  Core  │ │
│ └────────┘ └────────┘ │
│ ┌────────┐ ┌────────┐ │
│ │  Core  │ │  Core  │ │
│ └────────┘ └────────┘ │
└───────────────────────┘
```

В таким случай будет ощущение что в одной машине как будто не один процессор а целых 4. 

После появления многоядерных процессоров у нас как будто появилось несколько рук которые параллельно могут выполнять полезную работу. 

### SIMD

**Single Instruction, Multiple Data** — одна инструкция обрабатывает сразу несколько элементов данных параллельно.

Чтобы это понять, разберём по порядку три вещи: как процессор выбирает разрядность операции, что такое ALU и его ширина, и почему векторный блок — отдельная история от скалярного.

---

#### 1. Разрядность операции задаёт инструкция, а не «разрядность процессора»

«64-битный процессор» — ярлык про ширину _обычных_ регистров (`RAX`) и адресов памяти. Он не описывает физический предел того, что кристалл может обработать за такт.

Реальная ширина берётся из того, **какой регистр указан в инструкции**:

```
add al, 5     → 8 бит
add eax, 5    → 32 бита
add rax, 5    → 64 бита
```

Внутри процессора уже лежит сумматор максимальной ширины (скажем, 64 бита). Инструкция говорит, сколько из этой ширины реально использовать. Если число меньше — остальные биты забиваются нулями (**zero extension**) или знаком (**sign extension**).

> Выбор делает не процессор «сам по себе» — его делает компилятор/программист, когда пишет `eax`вместо `rax`. CPU лишь честно выполняет то, что закодировано.

Отдельно: **размер самой инструкции в байтах** (opcode + ModRM + immediate + префиксы) — это про то, сколько места код операции занимает в памяти. К ширине данных это отношения не имеет: `add al, 5` (2 байта) обрабатывает 8 бит, а `add rax, 5` (6 байт, с префиксом `REX.W`) — 64 бита. Совпадение, что длиннее — не значит "шире" по смыслу; просто регистр `RAX` требует лишнего байта-префикса, чтобы его указать.

#### 2. ALU — физический блок с фиксированной максимальной шириной

ALU (арифметико-логическое устройство) — схема с двумя входами и выходом, которая умеет складывать, сравнивать, делать логику. Максимальная ширина входов зашита в кремний.

Складывать одно число как единое целое дорого при большой разрядности: перенос из младшего бита должен дойти по цепочке до самого старшего. Поэтому 512-битной _скалярной_ арифметики никто не делает — она была бы медленной, а 64 бит с запасом хватает на любые практические целые числа и адреса (2⁶⁴ = 16 эксабайт).

#### 3. Скалярный и векторный блоки — разное железо

Внутри одного ядра есть несколько независимых исполнительных портов:

- **Целочисленный ALU** — работает с `RAX/EAX/AL`, максимум 64 бита, один сумматор с цепочкой переноса.
- **Векторный исполнительный блок** — отдельная схема, работает с `XMM/YMM/ZMM`, ширина до 512 бит (AVX-512).

Декодер видит мнемонику (`add` vs `vaddps`) и направляет её на нужный порт. Это буквально разные схемы на кристалле — они могут работать в одном такте одновременно, независимо друг от друга.

Историческое доказательство, что это разные оси: Pentium III (1999) был **32-битным** процессором, но уже имел 128-битные регистры `XMM`. Ширина SIMD никак не привязана к разрядности скалярного тракта.

> Нюанс: ширина _регистра_ и ширина _физического исполнительного блока_ тоже могут расходиться. У AMD Zen 1 регистры `YMM` были 256-битными по спецификации, но исполнительный блок — 128-битным, поэтому каждая AVX-инструкция шла в два прохода. Для программиста это невидимо, просто медленнее.

#### 4. Внутри векторного блока — не одно широкое число, а дорожки (lanes)

Вот здесь ключевой момент, который снимает вопрос «разве туда столько поместится». 512-битная SIMD-операция — это **не** сложение одного 512-битного числа (см. пункт 2, почему это было бы медленно). Это широкий тракт, разрезанный на независимые дорожки фиксированной ширины, между которыми перенос не идёт:

```
[A1][A2][A3][A4][A5][A6][A7][A8]
 +   +   +   +   +   +   +   +
[B1][B2][B3][B4][B5][B6][B7][B8]
 =   =   =   =   =   =   =   =
[C1][C2][C3][C4][C5][C6][C7][C8]
```

Каждая дорожка — это по сути отдельный маленький сумматор, ничем не сложнее тех, что были в процессорах 90-х. Их просто поставили в ряд. Именно независимость дорожек делает такую ширину дешёвой в реализации.

Ширина дорожки задаётся кодом операции — та же логика, что и в п.1, только теперь применяется не к одному числу, а к нарезке всего тракта:

|Тип элемента|Ширина дорожки|Элементов в 128 бит (SSE)|в 256 бит (AVX)|в 512 бит (AVX-512)|
|---|---|---|---|---|
|`int8`|8 бит|16|32|64|
|`int32` / `float`|32 бита|4|8|16|
|`int64` / `double`|64 бита|2|4|8|

Регистры по поколениям:

|Набор инструкций|Регистры|Макс. ширина|Появился|
|---|---|---|---|
|SSE|`XMM0–15`|128 бит|1999|
|AVX/AVX2|`YMM0–15`|256 бит|2011/2013|
|AVX-512|`ZMM0–31`|512 бит|2016|

#### 5. Зачем это нужно

Одна инструкция вместо восьми экономит не только на самих сложениях, но и на декодировании, инкременте счётчика цикла и предсказании переходов — этих накладных расходов становится в 8 раз меньше.

Кроме арифметики, SIMD умеет:

- **FMA** (`a*b+c` за одну инструкцию) — основа матричных умножений и ML;
- **сравнение через маску** — результат не `true/false`, а вектор из единиц/нулей по дорожкам, дальше по маске делают выборку без ветвлений (`if` плохо ложится на SIMD);
- **shuffle/permute** — перестановка элементов внутри вектора;
- **horizontal sum** — свернуть вектор в одно число.

Где применяется: графика, аудио/видеокодеки, матричные операции в ML, `memcpy`/`strlen` в стандартной библиотеке, парсеры (simdjson), сканирование столбцов в колоночных БД, хеши и шифрование.

Общий признак задачи под SIMD: **много однотипных данных подряд в памяти, к которым применяется одна и та же операция**.

#### 6. Ограничения

- Данные должны лежать **подряд** в памяти (массив, не связный список).
- **Ветвления плохо ложатся** — вместо `if` считают обе ветки и выбирают по маске.
- **Хвост массива**: если элементов 100, а в вектор влезает 8, последние 4 обрабатываются отдельным скалярным кодом.
- Не все процессоры поддерживают всё — AVX-512 есть не везде, нужна проверка через `CPUID`.
- AVX-512 на части процессоров Intel снижает частоту ядра — на смешанной нагрузке может быть невыгодно.

#### 7. SIMD и многопоточность — разные оси

|                      | Один поток данных  | Много потоков данных  |
| -------------------- | ------------------ | --------------------- |
| **Одна инструкция**  | обычный код (SISD) | **SIMD**              |
| **Много инструкций** | редкость           | многоядерность/потоки |

SIMD — параллелизм **внутри** одного потока исполнения. Многопоточность — параллелизм **между** ядрами. Эти оси перемножаются: 8 ядер × 8 `float` в AVX2 = 64 элемента одновременно.
