Мы уже решали задачу "выполнить что-то ровно один раз, даже если к этому коду одновременно рвётся тысяча горутин" — руками, через `atomic.Bool` и `CompareAndSwap` (см. [[Synchronization Primitives#Зачем нужен Compare-And-Swap (CAS)|Synchronization Primitives]]). Рабочий, но низкоуровневый способ — на каждый такой случай в проекте пришлось бы копипастить этот CAS-паттерн заново. Для этого в `sync` есть готовый примитив: `sync.Once`.

## Проблема без Once

```go
package main

import "fmt"

var config map[string]string

func loadConfig() {
	config = map[string]string{"env": "prod"}
	fmt.Println("config loaded")
}

func GetConfig() map[string]string {
	if config == nil { // ⚠️ TOCTOU — та же гонка, что и с ручной инициализацией
		loadConfig()
	}
	return config
}
```

Если `GetConfig` дёрнут одновременно из нескольких горутин без синхронизации — `loadConfig()` может выполниться не один раз, а несколько (data race и на самой проверке `config == nil`, и на записи в `config`).

## API

```go
type Once struct { ... }

func (o *Once) Do(f func()) // выполняет f ровно один раз за всю жизнь Once
```

```go
package main

import (
	"fmt"
	"sync"
)

var (
	config map[string]string
	once   sync.Once
)

func loadConfig() {
	config = map[string]string{"env": "prod"}
	fmt.Println("config loaded")
}

func GetConfig() map[string]string {
	once.Do(loadConfig)
	return config
}

func main() {
	var wg sync.WaitGroup
	wg.Add(10)

	for i := 0; i < 10; i++ {
		go func() {
			defer wg.Done()
			GetConfig()
		}()
	}

	wg.Wait() // "config loaded" напечатается ровно один раз
}
```

Сколько бы горутин ни вызвали `once.Do`, `loadConfig` реально отработает только у первой — остальные просто дождутся её завершения и вернутся, не выполнив `f` повторно.

## Что внутри

Упрощённо `sync.Once` устроен как раз через паттерн double-checked locking — быстрая проверка без блокировки плюс мьютекс на медленном пути:

```go
type Once struct {
	done uint32
	m    Mutex
}

func (o *Once) Do(f func()) {
	if atomic.LoadUint32(&o.done) == 0 { // быстрый путь: почти всегда сюда и попадаем
		o.doSlow(f)
	}
}

func (o *Once) doSlow(f func()) {
	o.m.Lock()
	defer o.m.Unlock()

	if o.done == 0 { // проверяем ЕЩЁ РАЗ, уже под мьютексом
		defer atomic.StoreUint32(&o.done, 1)
		f()
	}
}
```

**Зачем проверка дважды.** Первая, в `Do`, — без мьютекса, дешёвая атомарная загрузка: после первого выполнения `f` она отсекает все последующие вызовы почти бесплатно, вообще не трогая мьютекс. Вторая, уже внутри `doSlow` под `m.Lock()`, нужна потому, что несколько горутин могли одновременно пройти первую проверку (`done` у всех ещё `0`) и одновременно попасть в `doSlow` — мьютекс пускает их по одной, и только первая реально увидит `done == 0` и вызовет `f`, остальные увидят уже `1` и молча выйдут.

> ⚠️ Обрати внимание: `defer atomic.StoreUint32(&o.done, 1)` стоит **до** вызова `f()`, а не после. Это не опечатка — если `f` запаникует, `done` всё равно выставится в `1` через `defer`. Официальное поведение `sync.Once`: если `f` паникует, `Do` считает её выполненной — повторные вызовы `Do` больше никогда не вызовут `f`, даже если передать в них новый, "рабочий" колбэк.

## ⚠️ Подводные камни

**Once нельзя переиспользовать.** Если внутри `f` что-то пошло не так (не паника, а просто ошибка, которую вернули или залогировали) — следующий `Do` его не перезапустит, что бы вы туда ни передали. Обработку такой ошибки нужно закладывать внутрь самого `f` (например, сохранить `error` в отдельную переменную), а не надеяться, что `Do` сам всё повторит.

**Разным вызовам Do должен соответствовать один и тот же смысл.** `Once` запоминает не "какую функцию выполнить", а сам факт "уже выполнялось". Второй `Do` с совершенно другой функцией просто её проигнорирует:

```go
var once sync.Once

once.Do(func() { fmt.Println("A") }) // напечатает "A"
once.Do(func() { fmt.Println("B") }) // ничего не напечатает — Once уже "использован"
```

**Не вызывай Do изнутри f того же Once.** `sync.Mutex` внутри `Once` не реентерабельный — та же ловушка, что и с [[Synchronization Primitives#⚠️ Подводный камень — рекурсивная блокировка|рекурсивной блокировкой мьютекса]], гарантированный deadlock.

## OnceFunc / OnceValue / OnceValues (Go 1.21+)

Обёртки над тем же `Once`, но без ручного заведения переменной под результат:

```go
var getConfig = sync.OnceValue(func() map[string]string {
	fmt.Println("config loaded")
	return map[string]string{"env": "prod"}
})

func main() {
	cfg := getConfig()  // первый вызов реально загружает и печатает
	cfg2 := getConfig() // второй — просто возвращает закэшированный результат
}
```

`sync.OnceFunc(f func())` возвращает функцию без результата, `sync.OnceValue[T](f func() T)` — с одним результатом, `sync.OnceValues[T1, T2](f func() (T1, T2))` — с двумя (например, значение и ошибку). Внутри — тот же `done`/`Mutex`, что и выше, просто без необходимости заводить отдельную глобальную переменную под кэш результата.
