# How Linux Works (Brian Ward)

**Рельс:** C — Лёгкий · **Статус:** в очереди (после Concurrency in Go) · **Оценка:** ~50 ч
**Зачем:** закрывает конкретные дыры: iptables, разделы диска, ext4, как ядро ищет файл в дереве.

> Читается **только с открытой виртуалкой**. Глава без «сделал руками» не считается прочитанной.
> Отдельная VM, которую не жалко сломать. Снапшот перед каждой главой.

## Понимание

- [ ] Гл. 1–2 — Общая картина, основы командной строки
- [ ] Гл. 3 — Устройства, `/dev`, udev, sysfs
- [ ] Гл. 4 — Диски и файловые системы: разделы, mkfs, ext4, inode, mount
- [ ] Гл. 5 — Загрузка ядра
- [ ] Гл. 6 — Пользовательское пространство при старте
- [ ] Гл. 7 — systemd, юниты, журнал
- [ ] Гл. 8 — Процессы и использование ресурсов
- [ ] Гл. 9 — Сеть и конфигурация: маршрутизация, netfilter/iptables
- [ ] Гл. 10 — Сетевые приложения и сокеты
- [ ] Гл. 11 — Шелл-скрипты
- [ ] Гл. 13–14 — Пользовательское окружение, десктоп *(бегло)*
- [ ] Гл. 15–17 — Разработка, сборка, виртуализация

## Артефакт

**Виртуалка, развёрнутая с нуля и по памяти, без гугла:**

- [ ] Разбивка диска на два раздела
- [ ] Один отформатирован в ext4, смонтирован, прописан в `/etc/fstab`
- [ ] Свой systemd-юнит: сервис стартует при загрузке, логи видны в `journalctl`
- [ ] Правила iptables: политика по умолчанию DROP, открыт один порт, работает NAT
- [ ] Разобрать путь поиска файла: путь → dentry → inode → блоки. Записать своими словами
- [ ] Сломать систему намеренно (битый fstab) и починить из recovery
